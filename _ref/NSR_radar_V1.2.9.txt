1. 概述
《NSR 雷达系统通信协议》是纳雷NSRX 系列雷达的通信协议，用于NSRX 系列雷达及与其
相连接的设备间进行数据交互。该协议对通信方式进行简要说明，对通信过程中数据包格式进行
约定，对雷达支持的全部协议命令进行详细说明，对一些较为复杂且需要多条协议命令配合完成
的通信功能进行补充说明。协议中涉及一些可能实时补充与修改的附加信息，这部分内容以附录
的形式出现在文档末尾。
使用该协议的雷达包括NSR100、NSR100W、NSR300W，更多适用于该协议的雷达参考附录
部分雷达型号。不同的雷达支持的协议命令可能所有不同，特此申明。
如果没有特别说明，目标采用目标传输协议进行传输。特别地，目前NSR800W 目标输出采
用点云传输协议。
因为通信协议中的命令与雷达功能息息相关，雷达功能又是不停变更优化的，所以通信协议
中部分内容可能出现稍许调整。如果出现雷达行为与通信协议不符合的情况，我们会以通信协议
为准对雷达进行修改。
2. 通信方式
NSRX 系列雷达支持多种通信方式，比如支持TCP、UDP 及web socket 等网络通信方式，还
支持串口、SPI、CAN 等总线通信方式。
TCP、UDP、串口为双向通信。
Web socket、SPI、CAN 仅输出目标信息传输内容。
Web socket 接口目前不采用本文档所述的通信协议进行通信，而是采用JSON 格式进行目标信
息传输。JSON 格式是一种对人类友好的数据格式，因而web socket 接口具体传输内容可以直接
参考调试信息，不在本文具体展开。
第三方开发时，需要综合考虑不同连接方式的特点进行合理选择。
2.1.TCP 通信
采用TCP 通信方式，雷达作为服务端，其他设备作为客户端。
由客户端主动发起连接，与雷达建立连接。
雷达作为服务端，最大支持5 个客户端接入。
通信端口默认为50000。
2.2.UDP 通信方式
采用UDP 通信方式，雷达作为服务端，其他设备作为客户端。
由客户端主动发起任一数据通信命令（建议使用“读取雷达状态”命令）后，与雷达建立连
接。
通信端口默认为8100。
通信双方采用心跳报文维持连接。服务端（雷达）发送心跳报文，客户端接收心跳报文之后

回复应答数据。默认心跳间隔时间为5 秒左右。关于心跳参考心跳包。
2.3.串口连接
串口采用全双工通信。
串口波特率：115200。
校验方式：无校验。
流控：无。
停止位：1 位。
2.4.Web socket 连接
连接方式是标准的web socket 连接，端口为默认的web socket 端口：1883。

3.3.数字表示说明
3.3.1. 小端模式
如无特别说明，数字取小端模式。例如整形变量5，在内存中十六进制表示为
【0x05, 0x00, 0x00, 0x00】。
其中，0x05 为内存的低字节。
3.3.2. 大端模式
某些数据因为一些诸如约定俗成的原因采用大端模式传输。像IP 地址使用大端模式，即IP
地址高位字节在前，例如IP 为192.168.10.123，对应于4 个字节存储【0xC0 0xA8 0x0A 0x7B】
3.3.3. 通用变量
整形变量占4 个字节。
浮点型点4 个字节。

3.3.4. 短浮点数
尽管这一数据类型看上去有点奇怪，但出于历史原因我们还是保留该数据类型，该数据类型
只出现在接收机性能测试及添加坐标设置这两个命令当中
短浮点数，占3 个字节，从低位到高位3 个字节，分别定义如下：
字节1：最高位为符号位（0 为正，1 为负），0~3 位为小数位，小数位范围0.0～0.9。
字节2：整数部分高八位。
字节3：整数部分低八位。
举例说明：-250.3 表示为二进制【1000 0011 0000 0000 1111 1010】，表示为十六进制【0x83 0x00
0xFA】。

6.6.HTTP 通信API
带WEB 功能的雷达，可以通过HTTP 通信API 的方式进行部分参数的读写。
6.6.1. 对像读取
输入：【radar ip】/cgi-bin/cmd.cgi?action=get_object&object=【object name】
返回：
{"status":"0", "msg":"【value】"}
说明：
Object name 为待读取的对像名称，字符串形式，可以取值为：“in_channel_0”。
Value 为返回的对像状态值。如果对像为in_channel_0，则状态值表示电平状态，0 表示低电平，
1 表示高电平。
